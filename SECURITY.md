# Security policy

InspectCoder CJ compiles and executes the project it is asked to inspect.
Use it only on code and dependencies you trust; it is not a sandbox for hostile native programs.
Model transports send declared repair context to the selected provider under that provider's policies.
Review candidate diffs and keep assertions independent.

Do not disclose provider tokens, private source, environment dumps, or unredacted traces in public issues.
For a security concern, use GitHub's private vulnerability reporting on this repository when enabled.
If that feature is unavailable, first open an issue asking for a private contact without including exploit details.
No private reporting endpoint is claimed to exist until the repository owner enables or publishes one.

The user config accepts tool paths only and must not contain credentials.
Workspace trust, canonical project boundaries, bounded outputs, explicit application permission, immutable acceptance and stale-source checks are part of the supported client contract.
Optional SDK/model dependencies and host software have their own update and advisory policies.
Only the configurations listed in GETTING_STARTED.md are certified.
